# Красный билет — Telegram-бот для розыгрышей

Mini App с красным оформлением, регистрацией по кнопке «Участвовать» и выбором одного случайного победителя. Python 3.10+, SQLite, Telegram Bot API; для production — Gunicorn, systemd и HTTPS через nginx. Приложение предназначено для Linux.

## Быстрый запуск для получателя архива

В архиве находятся исходный код, тесты и установочные скрипты. Деплой на сервер пока не выполнялся. Установка ниже рассчитана на сервер с **уже работающим nginx, systemd, Python 3.10+ с venv и Certbot**. Перед запуском проверьте существующего бота и используемый веб-сервер, как описано в разделе «Размещение рядом с другим ботом». Если 80/443 обслуживает Docker, Caddy или другой прокси, настройку HTTPS нужно адаптировать.

Данные для настройки:

- Сервер: `root@5.35.81.138`. Доступ получить отдельно у владельца.
- Telegram ID мастер-аккаунта: `1906596928`.
- Токен нового бота получить отдельно у владельца и ввести при установке. Токен и SSH-пароль в архив не включены.
- Выбрать отдельный поддомен, например `raffle.example.com`, и направить его DNS A-запись на `5.35.81.138`.
- Подготовить email для выпуска HTTPS-сертификата. Во всех командах заменить примеры домена и email своими значениями.

Передайте архив на сервер из локального терминала:

```bash
scp shopen-raffle.zip root@5.35.81.138:/tmp/
ssh root@5.35.81.138
```

На сервере распакуйте его в новый каталог и установите приложение:

```bash
mkdir -m 700 /root/shopen-raffle-source
python3 -m zipfile -e /tmp/shopen-raffle.zip /root/shopen-raffle-source
bash /root/shopen-raffle-source/deploy/install.sh
```

Установщик запросит токен, ID `1906596928` и поддомен **без** `https://`. Создавать `.env` вручную при этом способе не нужно. Настройки будут сохранены в `/etc/shopen-raffle/env`.

Затем настройте HTTPS и включите Telegram-бота:

```bash
bash /root/shopen-raffle-source/deploy/publish-nginx.sh raffle.example.com owner@example.com
systemctl status shopen-raffle-web shopen-raffle-bot --no-pager
curl --fail https://raffle.example.com/healthz
```

Ожидаемый ответ проверки: `{"status": "ok", "configured": true}`. Отправьте новому боту `/start` и откройте Mini App. Проверьте участие с обычного аккаунта и запуск розыгрыша с аккаунта владельца. После пробного розыгрыша откройте следующий через панель организатора. Убедитесь, что ранее работавший бот продолжает отвечать.

Если установка остановилась, прочитайте её сообщение и логи:

```bash
journalctl -u shopen-raffle-web -u shopen-raffle-bot -n 80 --no-pager
```

Повторный запуск установщика поверх созданных каталогов запрещён: сначала выясните, на каком этапе он остановился. Не удаляйте `/var/lib/shopen-raffle` при устранении ошибок — там находятся участники и результаты.

## Что работает

- `/start` присылает кнопку открытия Mini App. Кнопка «Розыгрыш» также появляется в меню бота после запуска polling.
- Пользователь нажимает «Участвовать»: сервер сохраняет Telegram ID, ник, имя, время регистрации и последовательный номер билета. Если ника нет, отображается имя.
- Один Telegram-аккаунт получает один билет на розыгрыш. Повторные запросы возвращают тот же номер.
- Только `OWNER_ID` видит панель организатора и имеет доступ к административным API. Можно просмотреть участников и их ID постранично.
- «Запустить розыгрыш» атомарно закрывает регистрацию и выбирает один билет через `secrets.randbelow`. У каждого зарегистрированного билета одинаковая вероятность.
- Победитель сохраняется в SQLite. Повторное нажатие, повторный HTTP-запрос или перезапуск службы возвращают прежний результат. Отмены и переигрывания нет.
- Организатор может открыть следующий розыгрыш. Участники регистрируются заново, номера начинаются с 1, предыдущие записи сохраняются. Интерфейс показывает последние 10 результатов.
- Состояние и результат обновляются каждые 5 секунд, пока приложение открыто. Анимация рулетки показывается организатору при запуске; выбор выполняется сервером до анимации. Отдельные сообщения участникам с результатами не рассылаются.

Авторизация использует проверку HMAC подписи `Telegram.WebApp.initData` и срока действия по [официальной документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Имя, ник и права из JSON запроса не принимаются. Старые данные авторизации истекают через 24 часа; после этого приложение нужно открыть заново.

## Конфигурация

Скопируйте `.env.example` в `.env`, установите права `chmod 600 .env` и заполните:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен отдельного **нового** бота из @BotFather |
| `OWNER_ID` | Числовой Telegram ID организатора |
| `APP_URL` | HTTPS-адрес на выделенном поддомене, например `https://raffle.example.com` |
| `DATABASE_PATH` | Локальный путь к отдельному файлу SQLite |
| `INIT_DATA_TTL` | Срок действия initData в секундах, 60–86400 |

`.env` исключён из исходников и архива. Серверный пароль не записывается в проект. Токен требуется только серверу, в JavaScript его нет. Для запуска через systemd настройки лежат в `/etc/shopen-raffle/env`.

## Локальная проверка

Основная логика и тесты используют стандартную библиотеку Python, установка пакетов для них не нужна:

```bash
python3 -m unittest discover -s tests -v
node --check raffle/static/app.js
bash -n deploy/install.sh deploy/publish-nginx.sh
```

Для локального просмотра:

```bash
DEVELOPMENT=1 DATABASE_PATH=data/raffle.sqlite3 python3 -m raffle.web
```

Откройте `http://127.0.0.1:8088`. Вне Telegram доступен просмотр оформления; регистрация и панель владельца требуют подписанных Telegram-данных. Режим разработки не обходит авторизацию. В production этот встроенный сервер использовать не следует.

## Размещение рядом с другим ботом

Фактическая конфигурация сервера должна быть проверена до установки. Скрипты рассчитаны на systemd, Python 3.10+ с `venv`, уже работающий nginx с `sites-enabled` и установленный Certbot. Они не устанавливают системные пакеты и не меняют firewall. Если эти предпосылки не выполняются, нужна адаптация под сервер. Нельзя гарантировать совместимость с неизвестной конфигурацией, не подключившись к нему.

Изоляция нового приложения:

| Компонент | Отдельное расположение |
| --- | --- |
| Системный пользователь и группа | `shopen-raffle`, без интерактивного входа |
| Код и Python-зависимости | `/opt/shopen-raffle` и собственный `.venv` |
| База, WAL и резервные копии | `/var/lib/shopen-raffle`, доступ только новому пользователю и root |
| Настройки | `/etc/shopen-raffle/env`, `root:shopen-raffle`, права `0640` |
| Веб-служба | `shopen-raffle-web.service`, `127.0.0.1:18765` |
| Telegram polling | `shopen-raffle-bot.service` |
| Поддомен nginx | `shopen-raffle.conf`, отдельный `server_name` |

База не подключается к другой базе или боту. Общими остаются ресурсы ОС и nginx: службы ограничены по памяти и CPU. Другие службы не останавливаются и не перезапускаются. Для добавления поддомена используется проверка `nginx -t` и плавный `reload` nginx. При ошибке HTTPS скрипт удаляет только добавленный им конфиг. Установка останавливается, если собственные каталоги, пользователь или порт уже заняты. Скрипт первой установки не предназначен для обновления.

### 1. Проверить сервер

Подключитесь из терминала с сетевым доступом, пароль вводится интерактивно:

```bash
ssh root@5.35.81.138
```

Проверьте службы, свободную память, занятые порты и текущие контейнеры:

```bash
systemctl list-units --type=service --state=running --no-pager
ss -ltnp
free -m
df -h /
python3 --version
nginx -t
```

Если используется Docker, дополнительно выполните `docker ps`. Не меняйте существующие службы и токены. Особенно проверьте, кто обслуживает 80/443: если это другой прокси или контейнер, `publish-nginx.sh` применять без адаптации нельзя.

### 2. Подготовить домен и передать код

Добавьте DNS A-запись выбранного **отдельного** поддомена на `5.35.81.138`. Если есть AAAA-запись, она должна вести на этот же сервер с работающим IPv6; скрипт создаёт IPv4 listeners. Для выпуска сертификата поддомен должен открываться по порту 80. Mini App открывается по 443.

Архив создаётся локально без секретов, базы, окружения и Git:

```bash
bash deploy/package.sh
scp shopen-raffle.tar.gz root@5.35.81.138:/tmp/
```

На сервере:

```bash
mkdir -m 700 /root/shopen-raffle-source
tar -xzf /tmp/shopen-raffle.tar.gz -C /root/shopen-raffle-source
bash /root/shopen-raffle-source/deploy/install.sh
```

Скрипт запросит токен нового бота скрытым вводом, ID владельца и поддомен. Он установит зависимости **только** в новое виртуальное окружение и запустит web-службу. Telegram polling включается после проверки HTTPS.

### 3. Подключить HTTPS и Telegram

Для nginx с `sites-enabled`:

```bash
bash /root/shopen-raffle-source/deploy/publish-nginx.sh raffle.example.com owner@example.com
```

Замените домен и email своими. Certbot запускается в режиме `certonly --webroot`: nginx не останавливается. Если сертификат уже есть в `/etc/letsencrypt/live/<домен>/`, используется он. При ошибке конфигурации или сертификата добавленный виртуальный хост откатывается. Скрипт проверяет HTTPS локально с корректным SNI и только после этого запускает polling.

Убедитесь, что для сертификатов включено автоматическое продление (`systemctl status certbot.timer`). На некоторых серверах продление настроено через cron. После успешного продления nginx должен перечитать сертификат: можно добавить отдельный executable deploy hook Certbot со строкой `nginx -t && systemctl reload nginx`, если такой hook ещё не настроен. Не меняйте существующие задания продления.

Проверка после установки:

```bash
systemctl status shopen-raffle-web shopen-raffle-bot --no-pager
journalctl -u shopen-raffle-bot -n 40 --no-pager
curl --fail https://raffle.example.com/healthz
```

Откройте нового бота в Telegram, отправьте `/start`, запустите приложение и зарегистрируйтесь. Владелец должен увидеть панель организатора; другой аккаунт — только участие. Проведите пробный розыгрыш и откройте новый для реальных участников. После установки сопоставьте состояние существующего бота с проверкой до установки.

Кнопка меню Mini App и кнопка под `/start` настраиваются автоматически. Чтобы добавить большую кнопку запуска в профиль бота, включите Main Mini App через @BotFather → `/mybots` → новый бот → Bot Settings → Configure Mini App и укажите тот же HTTPS URL. Для работы кнопок `/start` и меню этот дополнительный шаг не нужен.

Бот отказывается запускаться, если у переданного токена уже есть webhook; существующий webhook не удаляется. При конфликте long polling (`409`) он завершает процесс, не пытаясь захватить другого бота.

## База и резервные копии

Таблицы: `rounds` (статус, время и автор запуска, номер победителя), `entries` (участники и номера), `bot_state` (offset Telegram polling). Номера уникальны внутри розыгрыша; Telegram ID также уникален внутри розыгрыша. `BEGIN IMMEDIATE` сериализует регистрацию и выбор победителя. Внешний ключ связывает победителя с реальным билетом. Отдельная файловая блокировка защищает первоначальную настройку SQLite при одновременном запуске процессов.

Согласованная резервная копия во время работы:

```bash
sudo -u shopen-raffle /opt/shopen-raffle/.venv/bin/python /opt/shopen-raffle/backup.py
```

Копия появится в `/var/lib/shopen-raffle/backups/`, права `0600`. Обычное копирование одного `.sqlite3` при активном WAL не заменяет этот способ. Для восстановления остановите **только** `shopen-raffle-web` и `shopen-raffle-bot`, сохраните текущую базу вместе с WAL, восстановите копию с владельцем `shopen-raffle`, затем запустите две новые службы.

## Проверка перед передачей

Успешно пройдены 16 автоматических тестов: подпись Telegram, права владельца, конкуренция регистрации/розыгрыша, постоянство результата, изоляция баз, WSGI API и обработка команд бота. Проверены синтаксис JavaScript и shell-скриптов, наличие ресурсов интерфейса и отсутствие секретов в архиве.

Работа на целевом сервере, реальный Telegram API, Gunicorn/nginx/systemd и внешний HTTPS не проверены: среда разработки блокировала SSH и установку пакетов по сети. Серверные службы и существующий бот не изменялись. После установки необходимо проверить внешний HTTPS и приложение в реальном Telegram-клиенте.
